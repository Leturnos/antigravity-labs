📖 Como Funciona uma LSM-Tree (Log-Structured Merge-tree)

1. Escrita de Alta Performance (Sem I/O Randômico)

Bancos relacionais tradicionais (B-Trees) gravam em páginas aleatórias do disco, causando alta latência. LSM-Trees (RocksDB, Cassandra) transformam qualquer gravação em I/O sequencial:

  • WAL (Write-Ahead Log): O registro é imediatamente gravado no final do arquivo de log com CRC32 para recuperação de desastres.
  • MemTable: O registro é inserido em memória em uma SkipList ordenada em tempo O(log n).

2. Flush de Memória para Disco

Quando a MemTable atinge seu limite (threshold), ela é congelada (Immutable) e gravada no disco como uma SSTable (Sorted String Table) imutável no Nível 0 (L0). O arquivo anterior do WAL é então descartado.

3. Anatomia de uma SSTable

  • Data Block: Registros ordenados consecutivamente em binário.
  • Sparse Index: Amostragem de chaves e offsets a cada N registros. Permite busca binária sem carregar o arquivo todo.
  • Bloom Filter: Vetor de bits probabilístico. Se o filtro disser que a chave NÃO está na SSTable, o disco nem é tocado (zero leituras!).
  • Footer (32 bytes): Contém os offsets e o número mágico AETH.

4. Compactação em Background

Conforme novas SSTables são criadas, arquivos velhos contêm chaves repetidas e lápides (Tombstones). A compactação roda uma fusão ordenada (k-way merge sort), descartando dados obsoletos e gerando SSTables densas no Nível 1.
